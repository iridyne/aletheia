# Code of Conduct

This project is a trading system, so collaboration quality affects more than
code style. Contributors are expected to protect trust, safety, and clear
decision-making.

## Expected Behavior

- Be direct, factual, and respectful.
- Critique code, evidence, and reasoning rather than people.
- State assumptions and uncertainty clearly.
- Keep reviews focused on bugs, safety, correctness, and maintainability.
- Respect the owner-controlled boundaries around risk, credentials, live trading,
  and execution.
- Use plain language when explaining operational impact.

## Unacceptable Behavior

- Harassment, insults, threats, or discriminatory conduct.
- Pressuring others to bypass safety gates or review steps.
- Publishing secrets, credentials, account data, or private runtime artifacts.
- Misrepresenting generated or inferred analysis as observed evidence.
- Hiding material risks, test failures, or uncertainty.
- Making live-trading, risk, or credential changes without explicit approval.

## Review Culture

Good reviews lead with concrete findings:

- What can break?
- What safety or trust invariant is affected?
- What test or evidence is missing?
- What is the smallest acceptable fix?

Disagreement is expected. Resolve it with code references, tests, reproducible
commands, and clear tradeoffs.

## Enforcement

The project owner may reject, revert, or block contributions that weaken safety,
trust, or collaboration quality. For serious conduct or security problems, use a
private maintainer channel rather than opening a public thread with sensitive
details.
