# TASK-2026-078 handoff

## Purpose

Remove `aletheia agent workflow` from the trading CLI (it was AI dev tooling contaminating the trading system entry point), protect concurrent same-machine agent claims with SQLite atomic locking, and move session ownership state out of git-tracked YAML into a machine-local `data/tasks.db`.

## Changes made

- **New**: `aletheia/agent_tasks_db.py` — SQLite claim layer for `data/tasks.db`; `claim_task_atomic()` uses `UPDATE...RETURNING` to eliminate the TOCTOU race between concurrent agents.
- **Modified**: `aletheia/agent_workflow.py` — `claim_task` now writes to SQLite instead of YAML `ownership`; `bootstrap` uses SQLite for branch lookup (with YAML fallback for backward compat); `complete_task` releases the SQLite claim; `create_task` no longer writes empty `ownership: {}`; `validate` drops `ownership` from required fields; `_assert_only_workflow_metadata_dirty` excludes `data/tasks.db*`.
- **Modified**: `aletheia/cli/operator.py` — removed `workflow_app` import and `add_typer` registration; `aletheia agent --help` no longer shows `workflow`.
- **New scripts**: `scripts/agent_task.py`, `scripts/agent_check_staged.py`, `scripts/agent_recovery_test.py` — standalone framework-agnostic wrappers.
- **Modified**: `scripts/hooks/pre-commit` — trust-boundary gate now calls `python scripts/agent_check_staged.py` (not `aletheia agent workflow`).
- **Modified**: `.agent/commands.yaml` — `workflow_bootstrap` points to `uv run python scripts/agent_bootstrap.py`.
- **Modified**: `AGENTS.md` — updated session-start and task-end commands.
- **Archived**: 74 completed/cancelled task packets and handoffs moved to `.agent/tasks/archived/` and `.agent/handoffs/archived/`.
