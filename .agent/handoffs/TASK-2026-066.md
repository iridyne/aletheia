# TASK-2026-066 handoff

## Purpose

Audit and repair the production trade path in business order from Opportunity through
Filter/Ranker, System Operator, Proposal, Risk, Execution/Position, Outcome, and
Attribution/Feedback. Cover both cross-module identity and each module's base behavior;
make only evidence-backed repairs and preserve live, credential, and risk-limit safety.

## Changes made

- Opportunity, Filter/Ranker, Operator, and Proposal handoff repairs are committed in
  `c7b4536e` through `3a41a9eb`: exact pending attribution, open-set ranking, explicit
  expiry, ranked-only wake-up, ordered bounded consumption, and durable idempotent
  Operator claim/finalization.
- Risk now records one authoritative immutable Proposal snapshot, rejects execution
  quantity/mode drift, reserves every unresolved accepted entry as possible exposure,
  and never treats a preflight result as execution authority.
- Bitget, OKX, Binance, and local paper execution preserve one Proposal -> RiskDecision
  -> Order path. Exchange acknowledgements no longer fabricate Fill or Position facts;
  only exact account-scoped private fills can atomically materialize Fill and Position.
- Stable client order IDs, explicit `submission_unknown`/`materialization_missing`
  states, pre-submit error recovery, partial-fill replay, and cross-Position identity
  checks prevent duplicate submission and wrong-position averaging.
- Paper entry and close write Order, Fill, Position, cash ledger, and durable audit in
  one transaction. Manual bulk close uses the same broker path, and operator
  notification starts only after commit.
- Reconciliation is account- and market-scoped across all three brokers. It never uses
  absence from open orders as proof of fill. Exact Bitget demo historical entry gaps
  can be recovered read-only; stale pending-close fields clear only after the complete
  durable close chain and fee economics agree.
- Bitget futures entries carry only the Proposal-approved original-order stop/take
  profit values. Spot and close orders omit them. Triggered Demo/Live Bitget TPSL and
  confirmed external disappearances converge through read-only exact private evidence;
  observed external closes are administrative and excluded from Learning.
- Position close uses a writer-lock snapshot guard, so concurrent averaging cannot
  settle PnL from stale quantity, entry price, fees, or funding evidence. A stale close
  aborts before any Order, Fill, cash, audit, or feedback write and can retry fresh.
- Outcome eligibility now requires verified entry/exit economics, complete funding
  semantics, and a relational Opportunity -> Proposal -> every entry Order chain.
  Mixed-proposal/mixed-opportunity multi-leg Positions retain lifecycle PnL but cannot
  enter Learning.
- Eligible Outcome feedback is delivered through a durable replayable outbox. Serenity
  post-mortems are idempotent by Position, and shadow-trade retries persist the first
  close-event price instead of sampling later markets. Same-instrument feedback uses
  the verified close fill; cross-instrument feedback requires a matching market type
  and a snapshot no older than ten minutes at the close event.
- The dashboard paper-approval endpoint and Proposals UI now accept only a stored
  `paper_internal + pending` Proposal. Demo/Live intent is never silently rewritten;
  unresolved states return 409, and execution exceptions are returned/audited without
  raw secret-bearing text.
- The deterministic control-loop simulator now generates complete Opportunity ->
  Proposal -> authoritative RiskDecision -> entry Order/Fill -> Position -> close
  Order/Fill chains through the production close path. Candidate refresh and
  performance replacement delete only DCLS-owned facts, preserve unrelated rows,
  rebuild the isolated paper ledger in event-time order, cover Position FK children,
  and reject the active/project data directory and all descendants before writing.
- Full-suite fixtures that previously asserted a filled/closed state directly now use
  canonical symbols and real authority/close producers. Historical fixtures keep
  opportunity, entry, close, funding, audit, hook-job, and paper-ledger time in one
  possible order; external fills carry exact venue order/fill identity. No production
  eligibility, Risk, Live, or execution rule was relaxed to make the suite pass.
- API/design docs and backend/frontend issue ledgers were updated to match the repaired
  behavior. Old executable fixtures that were meant to represent genuine Outcomes now
  carry a real Opportunity -> Proposal -> RiskDecision -> Order -> Fill -> Position
  chain; intentionally synthetic rows remain ineligible.
