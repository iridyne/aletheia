# TASK-2026-012 handoff

## Purpose

Make `base_commit` resilient to rebases and squash-merges so long-lived task
branches do not hard-fail `check --strict` when their original branch tip
becomes orphan — without abandoning the "base_commit must be a real commit"
invariant.

## Changes made

- `aletheia/agent_workflow.py::validate` emits severity `warning` (not
  `error`) when `base_commit` exists but is unreachable from HEAD. A
  non-existent commit is still an error.
- Added `rebase_base(task_id)` that resets `base_commit` to current HEAD and
  writes a `rebased_at` timestamp. Refuses tasks not in `in_progress` or
  `blocked`.
- Added CLI `agent workflow task rebase-base TASK-ID`.
- Added SDD claim AW-S08 in `spec_agent_workflow.py` and its invariant
  description in `docs/design/agent_workflow_contract.md`.
- Added 6 focused tests: orphan is a warning, missing commit is an error,
  rebase-base resets and stamps, refuses `done` tasks, CLI works, and
  `check` returns exit 0 with a WARNING line when only orphan is present.
