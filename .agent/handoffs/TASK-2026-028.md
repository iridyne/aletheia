# TASK-2026-028 handoff

## Purpose

Prevent real exchange orders below the executable venue minimum quantity, amount, or increment, and reject when executable rules are unavailable or stale.

## Changes made

- Added `execution/order_constraints.py`: a five-minute, executable-venue rule
  cache for Bitget, OKX, and Binance exchange modes. It reads CCXT market rules
  from the venue that will receive the order; stale rules are never reused if a
  refresh fails.
- Converts derivatives contract units into the system's base-coin quantity,
  applies the published minimum quantity, increment, minimum USDT amount, and
  maximum quantity, then rounds an opening order upward to a legal amount.
- Gateway keeps the existing first Risk Engine pass before external work. If
  exchange rules adjust the quantity, it runs Risk Engine again on that final
  quantity before broker submission. Missing, unsupported, inactive, or stale
  rules reject the proposal with an audit event and no order call.
- Added the EX-B05 execution contract check and focused unit/gateway tests.
- Updated `docs/design/execution_contract.md` Section 3.3 with the fail-closed rule.

## Risks

- The exchange remains the final authority: a market can still reject for a
  price move between validation and submission, balance, position mode, or a
  temporary exchange-side restriction. The new gate prevents orders below the
  last successfully refreshed published minimums and never guesses when rules
  are unavailable.
