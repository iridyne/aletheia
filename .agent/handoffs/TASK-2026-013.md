# TASK-2026-013 handoff

## Purpose

Stop the 8-heading handoff structure from degrading into ceremony on small
fixes. Small tasks like TASK-2026-002/003/004 currently degrade into
~120-byte placeholders — pure noise. Introduce a `packet_type` field so the
tool enforces the right shape per task.

## Changes made

- Added `packet_type` field to task schema (`standard` default; `tiny` for
  small fixes). Legacy packets without the field are treated as standard.
- Added `_TINY_HANDOFF_HEADINGS` and routed heading enforcement through a new
  `_handoff_headings_for(task)` so `complete_task`, `write_handoff`, and
  `validate` all use the task-appropriate list.
- `create_task` grew a `packet_type` argument and writes a 3-heading template
  when `tiny`.
- Added CLI `--tiny` switch for `task create`. Prints the packet_type back.
- Retro-classified TASK-2026-002/003/004 as `tiny` — text unchanged (they
  are historical; no rewrite), just the schema field added so future
  bootstrap/check sees them as tier-appropriate.
- Updated AW-S06 SDD claim + contract doc to describe both tiers.
- 9 new focused tests covering tiny creation, defaults, unknown packet_type
  rejection, tiny completion end-to-end, standard-still-requires-8, CLI
  behavior, and legacy-backward-compat.
