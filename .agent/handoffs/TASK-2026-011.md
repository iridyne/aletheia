# TASK-2026-011 handoff

## Purpose

Turn the AGENTS.md and trust_and_change_control.md §6.1 controlled-module list
into a machine-readable `.agent/policy.yaml` and enforce, via CLI `validate` and
the pre-commit hook, that any change touching those paths carries passing
spec verification recorded at a commit reachable from HEAD.

## Changes made

- Added `.agent/policy.yaml` (schema v1) — 10 trust-boundary entries covering
  every controlled module in `trust_and_change_control.md §6.1`. Each carries
  path globs and required command_keys.
- Added `.agent/schemas/policy.schema.json` for schema validation.
- Added 6 per-spec command_keys and 1 combo `workflow_trust_boundary_tests`
  to `.agent/commands.yaml`.
- Extended `aletheia/agent_workflow.py`:
  - `_load_policy()` reads and validates the policy shape.
  - `_match_trust_boundaries()` + `_path_matches()` resolve `**` and file-scoped
    globs against a changed-path set.
  - `validate(changed_since=...)` now emits an error for each touched boundary
    whose task packet lacks passing evidence recorded at a HEAD-reachable
    commit for one of the boundary's required command_keys.
  - `trust_boundary_hits_for_paths()` is a public helper the CLI and hook use.
- Added `check-staged` CLI subcommand that reads staged paths from stdin and
  fails when the trust-boundary policy is violated — the pre-commit hook
  invokes this so the glob semantics live in one place.
- Extended `scripts/hooks/pre-commit` to call the new subcommand.
- Added `tests/specs/spec_trust_boundary.py` (TB-S01..S07): fails on drift
  between AGENTS.md, `trust_and_change_control.md §6.1`, and `policy.yaml`;
  also asserts CLI/hook enforcement wiring.
- Added 8 focused tests in `tests/test_agent_workflow.py` covering: missing
  evidence, matching evidence, evidence at an ancestor commit, orphan-commit
  evidence, file-scoped globs, unrelated command_key, and the new CLI in
  three modes.
- Fixed AGENTS.md trust-boundary bullet drift: added the three modules that
  were in `trust_and_change_control.md §6.1` but not in AGENTS.md
  (`agent_shell/registry.py`, `agent_runtime/tool_registry.py`,
  `files/jsonl.py`) plus made every listed path repo-relative and added a
  reference to `.agent/policy.yaml`.

## Risks

- The `check-staged` CLI executes via `uv run` inside the pre-commit hook. On a
  fresh clone without `uv sync` the hook prints an install error instead of a
  policy verdict; this is deliberate (pre-commit is opt-in and the hook itself
  is versioned) but should be documented in CONTRIBUTING when the hook becomes
  a required install step.
- The initial policy uses `spec_execution` as a stand-in required command for
  several boundaries (bitget_auth/client, secrets, permissions, tool_registry,
  agent_shell/registry) that do not yet have dedicated specs. Future work should
  add per-boundary spec files and update `policy.yaml` — the drift test will
  catch a stale `required_command_keys` at that time.
