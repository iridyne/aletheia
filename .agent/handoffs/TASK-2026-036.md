## Changes made

- Added `portfolio.disappearance_confirmation`, which builds stable fresh-view
  identities, derives a non-secret logical account fingerprint, persists scoped
  disappearance candidates and immutable observations, rejects exact/time-regressed
  retries, and exposes readiness without close authority.
- Extended reconciliation classification with explicit view evidence. Stale,
  unconfigured, incomplete, ambiguous or wrong-account views now remain all-managed
  and cannot create, advance or resolve disappearance evidence.
- Wired scheduled/manual reconciliation to record one candidate on the first complete
  absence, advance only on a newer independent view, retain evidence across database
  reconnection, and resolve a pending candidate as `reappeared` with an atomic audit
  event when a fresh exchange row returns.
- Removed the scheduler/manual `run_reconcile` call to the legacy fallback-price orphan
  close. Even two confirmed absences leave the Position open and only surface
  `ready_for_verified_exit`, so RG-T06/T07 can add broker evidence and honest accounting
  before any state convergence. The legacy helper remains isolated with no production
  call site and an executable architecture lock.
- Kept Live alert-only: it may preserve scoped absence evidence but never adopts or
  closes. Demo external adoption remains unchanged and is independent from missing-local
  confirmation.
- Changed both reconciliation HTTP handlers to synchronous FastAPI handlers so the
  added SQLite evidence reads/writes run in the framework threadpool instead of blocking
  the uvicorn event loop.
- Made OI-B01 GREEN; updated the old orchestration regression, conformance budget,
  execution/data/Learning SDD, issue/implementation ledgers, route descriptions and
  DEVLOG. OI-B02/B03 remain explicit missing work.
