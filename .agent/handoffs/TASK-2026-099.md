# TASK-2026-099 handoff

## Purpose

Fix two macOS launchd autostart bugs: prevent `_auto_register_watchdog` from
silently re-enabling autostart after the user explicitly ran `disable-autostart`,
and surface that the gateway supervisor process stays alive after `bootout`.

## Changes made

- Classified as A (repair): incorrect persistent state that silently reversed a
  user's explicit decision.
- **Bug 1 root cause:** `_auto_register_watchdog` (lifecycle.py) checks
  `autostart_on_start` in config before calling `enable()`, but `disable-autostart`
  never wrote that flag. So every subsequent `gateway start` would see `enabled=False`
  and call `enable(source="auto")`, silently recreating the plist. Fix: CLI
  `disable-autostart` and `enable-autostart` now persist `runtime.autostart_on_start`
  (False / True) via `save_config` after a successful OS operation. The API route
  does the same.
- **Bug 2 design gap:** after `bootout`, the supervisor process (detached with
  `AbandonProcessGroup: True`) keeps the gateway alive. Users saw the gateway still
  running and thought launchd was restarting it. Fix: CLI prints a note ("gateway is
  still running — use `gateway stop`"); API adds `gateway_still_running: bool` to the
  disable response.
- Added `autostart_tests` command key to `.agent/commands.yaml`.
- Added regression test `test_lifecycle_skips_auto_register_when_user_disabled`.
