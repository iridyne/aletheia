# 该不该迁移到 R20 — 框架对比与决策 · 2026-09-24

接续两份前作：

- `ALPHA_MEASURABILITY_2026-09-24.md`（比的是**我们能不能度量 Alpha**）

本文回答三个问题：R20 为什么看起来效果好？两个框架哪个更好？该不该迁移？

## 证据边界（先划清，避免结论被过度使用）

| 能核查 | 不能核查 |
|---|---|
| R20 仓库全部源码（`34a0d29`, v8.3.0, 2026-09-24） | **R20 的真实胜率数字**。无其账户访问权 |
| R20 胜率/盈亏的**计算方式** | R20 实盘的样本量、时间跨度、资金规模 |
| 我方前瞻账本 714 笔成本完整样本 | Fedora 生产库（本文数据来自本机开发库） |
| 两边代码规模 | —— |

`https://www.r20.cn/` 是 JS 渲染营销页，仅有标题「R20量子交易系统 - 机构级加密货币波段量化终端」，
**未公布任何胜率/收益/方法论数字**。所以「R20 效果更好」目前是**主观观察，无第三方数据支撑**。

本文不试图证明 R20 不如我们。本文要说的是：**你拿来对比的那两个胜率，不在同一把尺子上。**

## 一、为什么 R20 的胜率看起来更高：四个原因，没有一个是「框架更好」

### 原因 1（最主要）：分母完全不同

| | R20 的胜率 | 我们的 29.7% |
|---|---|---|
| 统计对象 | **实际开仓并已平仓**的单子 | 扫描器**评估过的每一个候选** |
| 是否经过筛选 | 是，过了 75–80% 置信度门禁才开 | **否，筛选之前** |
| 数据性质 | 真实成交 | 反事实（假设当时开了会怎样） |

R20 的定义（`r20_backend/execution/circuit_breaker.py:131`）：

```python
if t.get("status") != "closed":  continue      # 只算已平仓的真实单
net = float(t.get("pnl", 0) or 0)              # pnl 已含真实手续费
if abs(net) < 0.01 and abs(gross) < 0.01: continue   # 剔除摩擦尘单
if net > 0:   out["win_trades"] += 1
elif net < 0: out["loss_trades"] += 1
win_rate = win_trades / (win_trades + loss_trades)
```

我们的 29.7% 是 `universe_forward_outcomes` 里 714 笔**全部候选**的净胜率——
**包含了所有我们本来会拒绝的单子**。

这两个数字的关系类似「高考录取学生的平均分」对比「全体考生的平均分」。
后者必然更低，且与教学质量无关。

**这一项单独就足以解释你观察到的差距。**

### 原因 2：真实成交 vs 估算成本模型

R20 的成本来自**交易所真实账单**（`r20_backend/dashboard_payload/bills.py`，OKX `account/bills`，
三所合并）。手续费是交易所实收，滑点**隐含在真实成交价里**——不需要估。

我们的成本是模型估算（`core/aletheia/universe/outcome_economics.py:71`）：

```python
spread_slippage_pct = (spread_bps + 2.0 * slip_bps) / 100.0
```

实测结果：

| | 实际点差 | 模型滑点 |
|---|---|---|
| R20 那 10 个主流币 | 1.419 bps | **15.49 bps** |
| 其余小币 | 1.397 bps | **18.74 bps** |

模型滑点是实际点差的 **11–13 倍**（`slippage_bps` 默认 5.0 × 双边 = 10 bps 硬加成）。
对主流币来说这个假设很可能过度悲观。我们的净收益 −0.297% 里，约 0.15–0.19% 来自这个假设。

**注意**：这**不代表**把滑点调小我们就赚钱了。上一份报告已证明方向毛收益按币聚类
t = −0.10，与 0 不可区分——成本砍到 0 也不赚。但它确实意味着**两边的净值口径不可比**。

### 原因 3：标的池纪律

R20 交易 **10 个手工挑选的主流永续**（`scripts/instrument_pool.py`）：

```
BTC / ETH（tier_1_bluechip，杠杆跟随全局上限）
SOL / XRP / DOGE / ARB / SUI / LINK / ADA / UNI（tier_2_momentum，杠杆收紧，DOGE 另加 conf_floor=80）
```

我们扫描自动发现的 universe。那 3.3 小时的 56 个币里包含：

| 类别 | 样本 | 币数 | 方向毛% | 净% | 胜率 |
|---|---|---|---|---|---|
| 加密原生 | 486 | 43 | +0.0145 | −0.2964 | 30.2% |
| **代币化股票/ETF** | 204 | 12 | −0.0177 | −0.3063 | 31.9% |
| **稳定币** | 24 | 1 | −0.0062 | −0.2367 | **0.0%** |

代币化股票 + 稳定币占全样本 **31.9%**。具体名单：
`GOOGL` `NVDA` `SAMSUNG` `SOXL` `SKHYB` `EWY` `SNXX` `MAGMA` `AMD` `INTC` `AMZN` `COIN` `RLUSD`

**`RLUSD/USDT` 是稳定币。** 24 笔样本的方向毛收益全部是 0 或 ±0.0099%——因为它钉住 1 美元。
扣掉 0.23% 成本后**必亏**，胜率 **0%**，而且这在数学上是确定的，不需要任何样本就能预判。

这是一个**准入过滤缺陷**，不是框架问题：universe 放进了结构上不可能有方向边缘的品种。
代币化股票同理——它们在美股休市时段价格几乎不动，却照样被当候选评估。

> 诚实补充：我原本假设「R20 只做主流币所以更好」，**用我们自己的数据否证了**。
> R20 那 10 个币在我们样本里表现**更差**（净 −0.3662%，n=110）而非更好。
> 所以差异不在市值大小，而在**是否该出现在候选池里**（稳定币/休市股票是硬错误，小币不是）。

### 原因 4：它在真的交易，我们没有

R20 是一个**闭合的回路**：10 个币 → LLM 决策 → 5 个拦截器门禁 → 三所真实下单 →
真实账单入台账 → 台账喂回 LLM 演化记忆（`scripts/self_improvement_engine.py:411`）。

我们的回路**从未闭合过一次**。本机 `positions`/`orders`/`fills` 全 0 行；
记忆里 Fedora 卡在风控止损距离门。

一个在跑的窄回路，永远比一个没跑起来的宽回路「看起来效果好」。

## 二、两个框架哪个更好：取决于要回答什么问题

两边**不是同一类东西**，不是同一件事的好坏版本。

| | R20 | Aletheia |
|---|---|---|
| 生产代码 | 192,116 行 | 259,592 行 |
| 测试代码 | 138,810 行 | 262,629 行 |
| 标的来源 | 10 个手工清单 | 自动发现 universe（455 members / 1170 registry） |
| 交易所 | OKX / Binance / Gate，**真实成交** | UTA 抽象 + 多模式，**尚未成交** |
| 决策 | LLM 逐标的 + 5 拦截器 | 扫描器 + 过滤器 + Operator + 风控 |
| 成本口径 | 真实账单（滑点隐含在成交价） | 估算模型（可调，当前偏悲观） |
| **反事实度量** | **完全没有** | **有，且成本归因完整** |
| 学习方式 | 把已平仓单原文喂 LLM 演化散文记忆 | OPE / 反事实账本 / contribution verdicts |
| 议会/多模型 | 有，但**生产未启用**（`council/__init__.py:25`） | —— |

### R20 结构性做不到的事

我 grep 了 R20 全仓：**没有 counterfactual、没有 shadow、没有 forward outcome、
没有任何「被拒绝的候选后来怎么样了」的记录。** `trades` 表只记真实成交。

这意味着 R20 **永远无法回答**：

1. 那道 75% 置信度门禁，是在挣钱还是在亏钱？（它不知道被拒的单后来涨没涨）
2. 这 10 个币是最优选择吗？（它不知道没交易的币表现如何）
3. 最近的盈利是策略有效，还是赶上了行情？（没有对照组）

它只能报告「我开的单赢了 N%」。这个数字在牛市里会很好看，且**无法区分运气与技能**。

### 我们有的、R20 没有的

`universe_forward_outcomes` / `filter_candidate_outcomes` 对**每一个候选**（不管是否开仓）
记录固定 horizon 的结果，并做三项成本分离归因（手续费 / 点差+滑点 / 资金费），
且 `net` 在成本未知时**返回 None 而不是 0**（`outcome_economics.py:42`）。

加上 `INDEPENDENT_UNIT_VERSION = "scanner-t0-cross-section-nonoverlap-4h/v1"`
（4 小时不重叠横截面才算一个独立样本），这套东西能回答上面三个问题。

**这是稀缺能力。** 上一份报告正是靠它得出「方向毛边缘 t = −0.10，与 0 不可区分」——
一个 R20 无论跑多久都产不出的结论。

### 但要说清楚：能力 ≠ 收益

我们有更好的尺子，**但还没有用它量出任何正边缘**，而且 3.3 小时 / 1 个独立单元
连「量不出」都算不上结论。R20 有更粗的尺子，**但它在真的交易**。

尺子再准，不交易就是 0 收益。这一点必须诚实承认。

## 三、该不该迁移：不该，但理由不是「4000 个 commit 可惜」

### 先把沉没成本这个框架拆掉

「已经有 4000 多个 commit，不想从零开始」——这个纠结本身是错的框架，两个方向都错：

- **往迁移的方向错**：R20 是 192k 行生产代码。迁过去不是「在成熟基础上继续开发」，
  是**接手另一个大型代码库**，并从头理解它的 5 个拦截器、三所适配、台账口径。
  这不比修我们自己的便宜。
- **往坚守的方向错**：4000 个 commit 不是资产。**资产是其中那 2–3 个模块**
  （前瞻账本 + 成本归因 + 独立单元定义）。其余大部分是可替代的工程。

真正该问的不是「保哪个代码库」，而是：**R20 做对了什么，我们能不能不重写就做到？**

### 答案：能，因为 R20 的优势主要是「政策」不是「架构」

逐条看 R20 做对的事，以及我们这边的对应改动量：

| R20 做的 | 我们的差距 | 我们要改什么 | 量级 |
|---|---|---|---|
| 只交易 10 个流动性好的主流永续 | universe 放进了稳定币和休市中的代币化股票（占 31.9%） | 准入过滤加一条硬排除 | **配置/一个过滤器** |
| 75–80% 置信度才开仓，宁可不开 | 我们对所有候选一视同仁地评估 | 一道门禁 | **一个门** |
| 真实成交进台账，滑点隐含在成交价 | 从未成交，滑点靠 5bps 硬假设 | 打通 Gate B（记忆：卡风控止损距离门） | **运行问题，非架构** |
| 已平仓单原文喂 LLM 演化记忆 | 我们有更严格的 OPE，但还没产出结论 | 先要样本 | **等数据** |

**没有一条需要换框架。** 最贵的一条（打通真实成交）在两个框架下都要做，
而且我们在 Gate B 已经推进到「准入 0→18」了。

### 迁移的隐性代价

迁过去等于**把 R20 的盲点变成我们的盲点**。我们会失去唯一能回答
「Alpha 是否存在」的装置，换来一个「能报告已开单胜率但无法判断门禁是否有效」的系统。

以你自己的目标衡量——「收益来源于理论上存在的 Alpha，要保证框架最终能捕捉到它」——
反事实度量正是**判断有没有捕捉到**的那个器官。切掉它，就只能靠盘面感觉判断系统好坏。

### 建议：混合，不迁移

按收益排序：

| # | 动作 | 为什么 | 量级 |
|---|---|---|---|
| 1 | **universe 硬排除稳定币与代币化股票** | RLUSD 胜率 0% 是数学必然；31.9% 的样本花在结构上无边缘的品种上 | 一个过滤器 |
| 2 | **打通 Gate B 拿到真实成交** | 没有真实成交，一切都是估算；也是唯一能校准那个 11 倍偏高的滑点假设的办法 | 记忆：卡止损距离门，不得调阈值 |
| 3 | **标的池先收窄到 R20 量级（10–20 个高流动性币）** | 不是因为主流币边缘更高（我们的数据否证了），而是降低维度、让样本快速积累到统计可用 | 配置 |
| 4 | **加一道置信度门禁，并用反事实账本验证它值不值** | 这是我们能做而 R20 做不到的事：装了门之后能测出门是在挣钱还是亏钱 | 一个门 + 现成账本 |
| 5 | **前瞻账本连续跑 ≥2 周**，按独立单元口径聚合 | 当前 1 个独立单元，决定不了任何事 | 运行纪律 |

第 4 条是这个混合方案的真正价值：**做完之后我们会同时拥有 R20 有的（真实成交战绩）
和 R20 永远没有的（门禁是否有效的因果证据）。** 迁移会永久放弃后者。

### 不该做的

- 不要因为「净收益为负」去调滑点参数把数字做好看。参数偏悲观是真的，
  但毛边缘是 0，调参救不回来，只会把唯一诚实的尺子弄坏。
- 不要把 R20 的胜率和我们的 29.7% 并列在任何报告里。分母不同，并列即误导。
- 不要在样本 = 1 个独立单元时判定任何策略族有效或无效。
- 不要为了「像 R20 一样」去掉反事实账本以求简化。那是我们唯一的稀缺资产。

## 四、一句话结论

**R20 的胜率更高，主要因为它统计的是「筛选后实际开的单」且用真实成交价，
而我们统计的是「筛选前所有候选」且用偏悲观 11 倍的滑点假设——分母和尺子都不同。**

**不该迁移。** R20 没有反事实度量，结构上无法判断自己的门禁是否有效；
这恰好是「确保框架能捕捉到 Alpha」所需的器官。

**该做的是把 R20 的三个政策决定搬过来**（收窄标的池、硬排除无边缘品种、加置信度门禁），
**同时打通真实成交**——这些都是配置和运行层面的事，不需要换框架。
