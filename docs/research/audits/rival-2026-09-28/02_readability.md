## 计数陷阱：四家的 LOC 数字都是虚高的

这一节必须放在最前面，因为它决定了上表能不能被引用。

### OpenAlice：36 万行 TS 中 4.9 万行不是手写逻辑

| 类别 | 路径 | 行数 | 判定依据 |
|---|---|---|---|
| protobuf 生成 TS | `packages/ibkr/src/protobuf/` | **34,425**（203 文件） | 文件头 `// Code generated by protoc-gen-ts_proto. DO NOT EDIT.` |
| vendored Python SDK | `packages/ibkr/ref/` | **31,415**（252 py） | IBKR 官方 SDK 原样拷贝，`ibapi/client.py` 单文件 7,502 行 |
| i18n 文案表 | `ui/src/i18n/locales/` | **14,816**（4 ts） | en/zh/ja/zh-Hant 各约 3.7k |
| 前端演示资产 | `ui/public/demo-studio/` | 14,539 | `studio.js` 5,808 + `studio.css` 7,130 |

交叉验证：`grep -l '@generated|DO NOT EDIT|Code generated by'` 命中**恰好 203 文件 / 34,425 行**，与目录计数完全相等 → 生成码边界干净。

**修正后**：手写 ts 317,177 + tsx 105,433 = **422,610 行**；**手写 Python 仅 298 行**（全是一次性 repair 脚本）。即 OpenAlice 是纯 TypeScript 项目，Python 侧没有任何自有实现。

### Vibe-Trading：44 万行 py 中 43% 是测试

441,257 行 py 中 **189,656 行（43.0%）是测试**。生产侧 248,957 行。另外 `.mp4` 2 个文件按 `\n` 计数出 103,802 "行"、`.png` 11 个出 60,963 "行" —— 任何"仓库规模"引用必须剔除媒体文件。

### nofx：23.7 万行里 Go 只有 7.8 万

`md` 37,954 行中 3,938 行是 `docs/i18n/` 翻译副本、2,521 行是第三方 arXiv 论文分析报告。Go 生产码 62,629 行（不含 `_test.go`）。

### tickflow：138,786 行 py 中 52,518 是测试

生产 `backend/app` 85,031 行。

**对 Aletheia 的含义**：Aletheia 的 268,953 行生产 py 是**没有 vendored、没有生成码**的净手写量（uv.lock 管理依赖，不 vendor）。跨仓比较规模时，Aletheia 的数字是六家中最"实"的之一。

## 各仓关键事实

### 六家里最反直觉的数字：TODO 计数普遍接近 0

| 仓库 | TODO/FIXME/HACK | 规模 | 解释 |
|---|---|---|---|
| tickflow | **0** | 85k 生产 py | 债务走 PR/commit body 或 `docs/` 的【设计】标记 |
| Aletheia | 3 | 269k 生产 py | 债务走 issue + `docs/` |
| nofx | 3 TODO / 0 其他 | 63k Go | 57 commit 浅历史，**更可能是"债未积累"而非"债被清理"** |
| OpenAlice | 6 TODO / 0 其他 | 423k 手写 | 债务外部化到 `plans/` 15,499 行 + `docs/` 24,960 行 + issue |
| Vibe-Trading | 15 | 249k 生产 py | 维护者倾向把解释写进注释并附日期/事故编号 |

**统一结论：不能把"TODO 少"读成"技术债少"，应读成"技术债不写在代码里"。** 对交接友好（代码干净），对新人不友好（债务线索在文档/issue 里）。

OpenAlice 的附带证据：commit 前缀 `fix: 73` vs `feat: 48` —— **修复是特性的 1.5 倍**，配合"6 个 TODO"，说明工作重心是在已有功能上加固。

### 注释质量：三家做到了"解释为什么"

这是本域最值得借的部分，因为它零成本、高收益。

**tickflow** —— 注释直接引用真实事故：
- `backend/app/watchdog.py:33-34` 直接引用 **"2026-09-07 冻结事故"** 作为设计依据
- `backend/app/price_limits.py:64-73` 解释无涨跌幅窗口的边际天数选择理由
- `backend/app/backtest/walkforward.py:1-7` walk-forward 目的与依赖说明

**Vibe-Trading** —— CI 注释即事故档案：
- `.github/workflows/test.yml:8-11` 记录 **"On 2026-08-06 twelve commits landed on main without a single push-event run being created"**，据此加 `workflow_dispatch`
- `:13-26` 记录 `npm ci` 审计端点 503 导致超时的实测数据（61s vs 4s）
- `:93-98` 解释为何必须装 `openbb`/`stats` extras：**"skipped is not tested"**
- `:135-143` 记录前端拆分的实测原因（Python 3.11 leg 539s/600s 预算）

**OpenAlice** —— 解释交易语义：
- `services/uta/src/domain/trading/UnifiedTradingAccount.ts:565-571` 解释为何在 dispatch 前而非 staging 时复检数量：**"a position can change after the UI or CLI created its proposal"**
- `vitest.config.ts:40-51` 解释为何 CI 限 1 worker，含具体故障历史（"two workers still saturate a two-core CI runner"）
- `src/domain/analysis/simulate.ts:1-19` 19 行文件头列出 5 条退出规则语义 + 依赖方向说明

**Aletheia 对照**：`tests/audit/test_no_silent_except_pass.py:1-36` 的文档字符串是同一风格（说明这一刀查什么、如何使用门禁、当前 baseline 42 处的来历、"这是耻辱榜，不是许可证"）。**这个习惯已经在 Aletheia 存在，值得扩展到 `core/` 的关键决策点。**

### 类型化的两极

**最好的**：Aletheia（288 BaseModel）、OpenAlice（zod 全量 schema + `z.infer` 导出类型，`src/core/config.ts:240`；判别联合 `{ meta: WsMeta } | { error: 'unavailable' | 'unknown' }`，`src/server/cli.ts:79`）。

**最差的**：Vibe-Trading —— 39 个 pydantic 模块 vs **1,821 处 `Dict[str, Any]`**，且 **CI 里零静态类型检查**（无 mypy，ruff 配置存在但 CI 不跑）。跨模块边界全是裸 dict（`mcp_server.py`、`runner.py`、`trading/service.py` 的工具返回）。它的前端反而纪律最强（45 处 any）。

**OpenAlice 的 587 处 any 需要正确解读**：`as any` 346 + `: any` 241，但 `@ts-ignore` **0**、`@ts-expect-error` 仅 4。`as any` 是 `: any` 的 1.4 倍 → 主要是边界强制转型（券商 API 原始响应），且存在收口式转型（`as AlpacaOrderRaw`、先 `unknown` 再窄化）。1.85 处/千行不算失控。

### 命名一致性

- **OpenAlice**：两种风格并存但有规律——类文件用 PascalCase（`CcxtBroker.ts`、`UnifiedTradingAccount.ts`），其余 kebab-case（`trade-provenance.ts`）。`brokers/` 下严格遵循 `XxxBroker.ts` + `xxx-types.ts` + `xxx-contracts.ts` + `index.ts` 四件套。
- **tickflow**：矩阵层统一 `_matrix_*`/`valid_*`/`build_*` 前缀；builtin 策略统一 `META`/`EXECUTION_BACKEND`/`MATRIX_STRATEGY` 模块级常量协议。
- **nofx**：核心类型（`AutoTrader`/`StrategyEngine`/`Decision`）命名稳定贯穿多文件。

## 必须点明的幻象

1. **Vibe-Trading 最大的生产文件（6,656 行 `_legacy.py`）不是死代码，而是"为测试 monkeypatch 而存在的兼容层"**（`agent/cli/__init__.py:76-79` 自陈）。测试数量好看的另一面，是测试形状反向塑造生产代码。
2. **"TODO 为 0"在 tickflow 与 nofx 有完全不同的含义**：tickflow 是 948 commit + 36 作者下的主动习惯；nofx 是 57 commit 的浅历史（债未积累）。同一个数字不能同一个解读。
3. **OpenAlice 未做 AST 级函数长度统计**，其报告显式标 `[推断]` 不给最长函数结论。本表对应格留空，不用 48 个 >800 行文件推断函数长度。
4. **按 `wc -l` 统计仓库规模会把 `.mp4`/`.png` 算进去**（Vibe-Trading 的媒体文件出 16 万"行"）。任何跨仓规模对比必须声明剔除口径。
