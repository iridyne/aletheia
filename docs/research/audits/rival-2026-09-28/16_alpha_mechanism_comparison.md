# 16 · Aletheia vs R20：alpha 机制异同与可借鉴项（主线汇总）

> 日期：2026-09-28
> **性质：分析汇总。不含代码改动，不含需要等待验证的分支任务。**
> 素材来源：`04_alpha_source.md`（六家横评）、`06_execution_chain_gap.md`（执行链）、`10_forward_ledger_findings.md`（前瞻账本 99,465 样本）、`12_why_r20_turns.md`（R20 源码 + 台账实测）、`14_r20_prompt_alpha.md`（R20 prompt 分析）
> 本文只回答一个问题：**我们的 alpha 机制和 R20 的 alpha 机制有什么异同，能借鉴什么。** 一切"要不要接某个具体门禁"的技术分支不在本文范围（见文末"暂停的分支"）。

---

## 0. 一句话结论

**两边都没有被证明拥有稳定 alpha，但缺陷的性质完全不同：R20 是"结构上无法自证"，我们是"结构上能自证，但至今测出的是没有边缘"。** R20 能"转"靠的不是信号更准，是"默认不交易 + 只做少数确信机会"的执行纪律；我们缺的正是这条纪律，而不是更聪明的信号。

---

## 1. 两边 alpha 机制的整体形态对比

| 维度 | Aletheia | R20/AstraQuant |
|---|---|---|
| **信号来源** | 六个互斥的确定性打分函数（`continuous_scoring.py`），把 RS/RSI/funding/OI 等特征映射成 0-100 分 | 8 项启发式加权分（`score_composite_alpha`）+ LLM 逐标的判断 |
| **决策链条** | 打分 → 确定性 Ranker → Operator → Risk Engine，**全程无 LLM 判断这一步** | LLM 对每个标的输出 action/confidence/leverage/sl/tp → 4 道拦截器否决 |
| **拦截/风控层** | Risk Engine + Hard Gate（流动性/可交易性），**无市场大环境判断参与准入** | 4 道 fail-closed 拦截器：大盘趋势一致性、置信度门、ADX 震荡过滤、盈亏比门 |
| **默认姿态** | 打分产出候选后进入常规准入流程 | 4 道门任一不满足 → 直接不开仓（WAIT），**默认偏向不交易** |
| **标的池** | 算法自动发现 universe（455 members） | 10 个手工挑选的主流永续 |
| **回测/验证** | **零回测引擎**，靠前瞻账本（见下） | 有回测引擎，但**测的是内联 SMA(5)/SMA(15) 交叉，与实盘的 composite score 完全不同源** |
| **参数来源** | 零参数搜索代码；PCHIP 曲线控制点来源未追溯 | jerk 阈值等拍定，注释自认"业务语义不是可调参数" |
| **样本外/反事实验证** | 前瞻账本对每个候选（不论是否开仓）记录固定 horizon 结果 + 三项成本分离归因，**这是六家竞品结构上都做不到的** | 无任何反事实记录，只记已执行单，无法回答"被拒绝的候选后来怎样了" |

---

## 2. 相同之处

### 2.1 两边都没有证据支撑自己有稳定 alpha

**我们这侧**（前瞻账本 99,465 个成本完整样本，实测）：绝大多数（族×horizon）组合的方向毛边缘（扣成本前的纯信号质量）为负；仅两个组合方向为正（momentum 24h、mean_reversion 4h），但按币聚类统计检验不显著（t=+0.69、+0.92）。**结论：这是"策略没边缘"，不是"成本吃掉边缘"，且这个结论在 140 倍样本（714→99,465 行）上复现。**

**R20 那侧**（公开台账实测）：104 笔已平仓，总盈利 +200.90，但**SUI 单币贡献 +300.01（总利润的 149%）**，剔除后其余 80 笔净 −99.11；它主打的 BTC+ETH+SOL 三个币，29 笔净 −181.32。**结论：它的"能转"是单一标的一段行情的集中下注，不是可复现的稳定优势。**

**两边都在犯同一类错误的相反方向**：我们有工具能诚实地说"没有边缘"，却仍然想找到边缘；R20 没有工具去发现"自己也没有边缘"，只看到了表面的盈利数字。

### 2.2 两边的回测/验证机制都有同源性问题（性质不同）

我们**没有回测引擎**，所以不存在"回测和实盘不同源"的问题——但也意味着任何策略改动前都没有历史回放可用。R20**有**回测引擎，但它测的信号（SMA 交叉）与实盘用的信号（composite score）完全是两套代码，**"回测通过"对实盘毫无预测力**，而它的 README 还声称两者"exact same risk and sizing code paths"，这与代码事实矛盾。

---

## 3. 不同之处

### 3.1 我们有反事实度量装置，R20 没有——这是最大的差距，但方向对我们有利

我们的前瞻账本（`universe_forward_outcomes` / `filter_candidate_outcomes`）对**每一个被评估的候选**记录"如果当时开了会怎样"，不论最终有没有真开仓。这让我们能回答三个 R20 结构上永远回答不了的问题：

1. 置信度门禁是在挣钱还是在亏钱？（R20 不知道被拒的单后来涨没涨）
2. 标的选择是不是最优？（R20 不知道没被选的币表现如何）
3. 最近的盈利是策略有效还是赶上了行情？（R20 没有对照组，我们有）

R20 全仓搜索 `counterfactual|shadow|forward_outcome` 零命中——它只记录已执行单的账单。

### 3.2 R20 的"默认不交易"是我们完全没有的执行纪律

R20 的 4 道拦截器全部 fail-closed 到"不开仓"，而不是"降级后继续"：

- 大盘涨的时候禁止做空，跌的时候禁止做多（趋势一致性）
- AI 自己信心不够 75% 就不开
- 市场横盘震荡（ADX<18）就不开，注释直接写"杜绝在猴市横盘中过度交易损耗手续费"
- 盈亏比不够就不开

我们的准入检查（Hard Gate）只管流动性/价差/深度/数据新鲜度这类"能不能交易"的硬指标，**不含任何"现在该不该交易"的大环境判断**。打分产出候选后，只要过了硬指标就进入常规流程，没有一道"默认拒绝，少数条件全满足才放行"的关卡。

### 3.3 R20 的 alpha 大部分住在 prompt 里，我们的 alpha 全部住在代码里

这是两边最根本的架构差异，直接决定"能不能借鉴执行细节"这件事：

- R20：8 项启发式打分 + LLM 逐标的判断，**约 55% 的最终交易行为由 prompt 词句决定**（已独立验证：v8.4.0 两次大幅提高交易频率的改动，只碰了 prompt 文件和风控常量，**零信号代码改动、零回测验证**）。代码层的 4 道拦截器只有否决权，没有选择权。
- Aletheia：全链确定性打分，没有 LLM 逐标的判断这一步，**alpha 完全由代码里的打分函数和参数决定**。

**这意味着 R20 的很多"设计"本质上是 prompt 工程，不是可直接迁移的代码逻辑**——它的"顺势""震荡回避"这类判断标准，在它的架构里是靠 LLM 读懂 prompt 里的规则自己去执行；而我们没有这一层，任何借鉴都必须先转译成确定性规则，不能照抄。

## 4. 可借鉴项（已用我们自己数据初步验证方向，未证明显著，未接入代码）

| # | 从 R20 借鉴什么 | 我们目前的状态 | 初步验证结果 |
|---|---|---|---|
| 1 | **默认不交易 + 少数条件全满足才放行**的执行纪律 | 没有大环境判断参与准入，打分产出候选即进入常规流程 | 用简化代理（BTC 当天涨跌）粗测过"顺势"这一条规则，方向合理（24h 上从负边缘变正），但统计上不显著（t=+1.05），**尚未证明值得投入** |
| 2 | 参数出处写进生产代码注释（方法/样本量/日期），而不是拍脑袋 | PCHIP 曲线控制点来源未追溯 | 未验证 |
| 3 | 若要补回测引擎，必须与实盘强制同源（参照六家中唯一做对的 tickflow：回测和看板 import 同一个纯函数模块） | 目前零回测引擎 | 属架构设计原则，不是待验证的数字 |

**注意**：可借鉴项 #1 目前只有一个粗糙的初步信号，不构成"应该做"的结论——上一轮为了把这条测清楚，一度往下钻研到一个具体技术细节的验证方法，那个分支已经暂停（见下）。

---

## 5. 不该借鉴的

- **不要照抄 R20 的具体参数**（jerk 阈值 1.8、ADX<18、置信度 75）——它们都是拍的，没有校准依据，且它内部还有代码门与 prompt 标定值不一致的情况（代码门实际是 80，prompt 告诉 LLM 的却是 78/85）。
- **不要参考 R20 v8.4.0 的高频/激进参数**——那两次改动的 commit 明确写着"maximize broker commissions"，且区间内零回测验证，是被商业化激励扭曲的样本，不代表任何验证过的收益提升。
- **不要因为 R20"能转"就模仿它的标的池策略**（10 个手挑主流币）——它能转的证据本身就是单一标的运气（SUI），模仿它等于模仿一个未被证明稳健的样本。

## 6. 暂停的分支（供追溯，不是行动项）

在追查"可借鉴项 #1"（默认不交易的执行纪律）时，分析一度收窄到一个具体技术细节——我们代码里已有一个市场环境判断程序（`extensions/regime/detector.py`），但它连续多天只输出同一个状态，导致无法验证接入它是否有效。为了验证这一点，又发明了一个更粗糙的临时替代方法（用 BTC 当天涨跌代替判断程序）。

**这条分支已经暂停**，理由：

1. 判断程序的输出是否真的"卡死"尚未证实——没有核实过这段时间的市场是否确实持续处于对应状态。
2. 即使这道门值得接，它是 alpha 微调层面的具体实现问题，不是本文要回答的主线问题。
3. 为了验证一个尚未确定重要性的细节，又造出一个更简化的替代方案，这是过度深挖。

相关 issue（#3663、#3665、#3666）已标记暂停，待未来有独立证据支撑这个方向值得投入时再评估重启。

## 7. 本文未验证

- R20 那 4 道拦截器在其自身生产环境的**实际拦截率**——只读了代码，没有它的运行日志。如果拦截率很低，它的"能转"更多来自 LLM 判断或运气，门禁的贡献有限。
- Aletheia 打分函数（PCHIP 曲线）的控制点来源与是否曾校准。
- 可借鉴项 #1 在真实市场环境判断（而非简化代理）下是否显著——这正是暂停分支要回答的问题，目前无结论。
