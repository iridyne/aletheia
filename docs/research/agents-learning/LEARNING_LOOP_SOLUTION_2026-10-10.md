术语（首次出现即定义）：
- **决策**：入场规划器（Entry Planner）对一个候选做出的一次判断，输出 `EntryHypothesis`，取值 `ENTRY_PLAN` 或 `NO_PLAN`。
- **R**：以计划止损距离为 1 的盈亏单位。+2R = 赚了两倍初始风险。它和杠杆、仓位大小无关，所以不同交易可以直接比较。
- **回放**：把一个计划（入场价、止损、目标、时间上限）放到决策之后的 1 分钟 K 线上，按统一的成交和成本规则算结果。已有唯一实现 `core/aletheia/analytics/signal_replay.py`。
- **打法手册（playbook）**：本方案里唯一的教训存储，每条是一个有方向、有范围、带计数器的短规则。
- **建议级 / 授权级**：建议级 = 进入提示词，由 AI 自己决定用不用；授权级 = 代码强制，比如拦截候选、改仓位。

## 1. 先回答"真正的自我进化"是什么

把"从错误中学习"拆到最小，它要求四件事同时成立。缺任何一件，都只是在写日记：

1. **知道自己犯了什么错**：分得清"判断错"和"运气差"。只看盈亏分不清（这叫结果偏差）。
2. **把错误变成下次能用的规则**：规则要短、有适用范围、有方向（该做 / 别做）。
3. **下次真的用上了**：规则进入了决策，而且有记录证明 AI 照做了还是没照做。
4. **能验证用了之后更好**：有对照、样本足够、有害的会自动撤回。

现在的系统卡在第 1、3、4 步（见评估报告 G1–G8）。AstraQuant 做到了第 2、3 步，但第 1、4 步没做（§2）。学术界在交易场景下也没人证明第 4 步成立（评估报告 §5）。

**本方案最关键的一个改动：学习单元从"平仓交易"换成"每一次决策"。**

- 平仓每月只有几十笔，任何统计都做不了。
- 决策每天都在大量产生。Fedora 全历史有 3,094 条冻结的规划输入（2026-10-09 能力追踪审计），而且每条都已经冻结了完整输入、带指纹，并记录了 AI 的结构化输出：机制、方向、失效位、支持和反对的证据（`core/aletheia/trading/entry_analysis.py:125-207`）。
- 只要用回放给每条 `ENTRY_PLAN` 算出扣成本后的 R，无论它最后成交没有，样本量就从"每月几十"变成"每天几十到上百"。这是解开评估报告 G2 样本量死结的唯一办法，而且所需部件全部已有。

## 2. 竞品 AstraQuant 的做法与取舍

AstraQuant 宣传"闭环经验自进化"。代码层面，它的主循环是 `scripts/self_improvement_engine.py::run_self_evolution`，每天 02/08/14/20 点运行：

| 环节 | AstraQuant 实际做法（证据） | 评价 | 我们取 / 弃 |
|---|---|---|---|
| 捕获 | 平仓瞬间写死 MFE/MAE（百分比和 R）、代码确认的离场机制、policy_hash；拿不到就记 null（`close_evidence.py:1-40`） | 好 | **取**：我们的回放和平仓结算统一输出这些字段 |
| 可观测性 | 代码给每笔单打可观测性标签，提示词禁止对不可观测的单子做因果归因（`observability.py:88-101`；`review_context.py:47-61`） | 好 | **取**：复盘输入带"证据完整度"，由代码计算，不让模型判断 |
| 决策理由 | 复盘**读不到** LLM 当时的理由（`load_closed_trades` 没有读 `model_reason`） | 弱：无法区分判断错和运气差 | **弃**：我们的复盘必须读冻结的决策理由 |
| 评判 | `net_pnl > 0` 就算赢（`review_context.py:37`）；R 口径的离场质量分析只在兜底路径运行 | 结果偏差 | **弃**：改为 R 口径加过程评判（§3.3） |
| 反事实 | 无：被拦下的单子、选择 WAIT 的机会都不进复盘 | 致命盲点 | **弃**：我们有回放和反事实账本 |
| 产物 | 自由文本"心法"，ADD / REVISE / INVALIDATE / NO_CHANGE 四种操作；只停用不删；CAS 并发写（`evolution_shield.py:405-514`） | 好（与 ACE 增量更新思路一致） | **取**：增量操作、只停用不删 |
| 入库门 | 正则"宪法 linter"：拦截放宽止损、加杠杆、马丁格尔等写法（`evolution_shield.py:67-197`） | 便宜有效的第一道防线 | **取** |
| 验证 | 健康分 = 胜率与期望值按 n/20 向中性收缩；样本 <10 不改分（`lesson_health.py:140-200`）。但用的是全部历史，**包括心法诞生前的交易**，属于样本内自评；入库门槛实为"窗口总笔数 ≥2" | 收缩和"不足就未知"值得学；样本内自评错误 | **取**收缩与 unknown；**弃**样本内自评，只用规则诞生之后的样本打分 |
| 极性 | 心法没有方向。"BTC 做空要谨慎"若 BTC 空单持续亏，反而低分归档 | 和我们 G4 是同一个 bug | **弃**：规则必须有极性 |
| 衰减 | 7 天一刀切，停止注入 | 好规则也会被淘汰 | **弃**：改为计数驱动 |
| 应用 | 按健康分取前 8 条注入提示词；面板和提示词用同一排序 | 好 | **取**：上限 5 条，面板显示实际注入了什么 |
| 自动调参 | LLM 每 6 小时给每个标的拍一个 0.5–1.5 乘数，**直接乘到真实保证金上**，无样本门槛、无平滑、无回滚 | 危险：把噪声直接放大成仓位 | **弃**：仓位类改动只能走授权级严格门槛 |
| 改进度量 | 无，只报整体胜率和 PF | 无法知道学习有没有用 | **弃**：做整包开关对照（§3.6） |
| 文档与代码 | 冷却池、策略权重被文档写成硬闸，实际读取函数写死 `return {}`，是死代码 | 和我们同一类病 | 引以为戒 |

**结论**：AstraQuant 的学习本质上是"每天让 LLM 读一遍账本写心得"。工程纪律（证据钉死、linter、增量更新、只停用不删）值得照抄。学习的认识论（只看盈亏、样本内自评、无对照）不能抄。它也没有任何证据证明这套自进化让收益变好了。

## 3. 方案：一条闭环、一份存储、两级权限

```text
决策(冻结输入 + EntryHypothesis)
  → ① 标签：回放 / 实际成交 → 扣成本 R、MFE/MAE、先触发谁
  → ② 复盘：代码先分类 + LLM 读"当时理由 + 后来路径" → 错误类型（封闭枚举）
  → ③ 提炼：同类错误在不同决策里反复出现 → 打法手册增量操作（新增 / 修改 / 退役）
  → ④ 入库门：linter + 去重 + 范围检查
  → ⑤ 应用：建议级 ≤5 条进入入场提示词；AI 必须逐条回答"用了没有、为什么"
  → ⑥ 计数：每次被用到后，用回放结果更新"帮到 / 坑了"计数 → 续期或退役
  → ⑦ 度量：整包开关随机对照 + 随时可停的序贯检验 → 有害自动关闭
  → 回到下一次决策
```

### 3.1 标签：每个决策一个统一口径的结果

- **对象**：每条 `ENTRY_PLAN`，无论是否成交。已成交的以真实成交为准，未成交或未触发的用回放。
- **口径（全链只用一种，修复评估报告 G8）**：扣全部成本后的 R、MFE/MAE（以 R 计）、先触发止损还是目标、持有时长、出场方式。时间窗由计划本身的止损、目标和时间上限决定，不再有 24h、4h、±0.5% 这些各自为政的窗口。
- **NO_PLAN 的收益记为 0**。这是它在系统层的真实效用，对照比较时不需要回放它。
- **回放的可信度要单独证明**：用真实成交的那几十笔检查回放与实际的偏差。偏差过大时，只把回放用于"相对比较"（实验组和对照组受到的偏差相同），不当作绝对收益。

### 3.2 决策记录补两个字段（D1，改 `EntryHypothesis`）

1. **`p_target_first`**：AI 估计"先到目标、后到止损"的概率，取 0–1。
   有了它，每个决策都能计算**校准度**，即 Brier 分：AI 说 60% 的那些单子，是否真有约 60% 先到目标。这是**不依赖盈亏、样本量最大的"判断质量"指标**，最接近人类交易员说的"我的判断准不准"。
2. **`lessons_considered`**：对注入的每条规则，回答 `{id, followed: bool, why}`。
   这条记录同时解决两件事：
   - "说到做到"检查。CLQT 论文实测 agent 的仓位系统性不遵循自己写下的分析。
   - 规则级的功劳分配（§3.6）。

### 3.3 复盘：先判过程，再判结果

人类交易员复盘的核心是"决策好坏 × 结果好坏"四象限，只从"决策差"中学习。具体分两步：

**第一步：代码先做确定性判定，不调用 LLM。**

| 检查 | 依据 |
|---|---|
| 引用的证据在截止时间是否真实存在 | `supporting_fact_refs` 对照冻结输入 |
| 失效位是否被尊重（有没有扛单、提前跑） | 计划与实际路径 |
| 执行偏差（成交价相对计划价） | 成交与计划 |
| 证据完整度 | 由代码计算，不完整的不做因果归因（学 AstraQuant） |
| 校准偏差 | 这笔的 `p_target_first` 与结果 |

**第二步：LLM 复盘。** 输入是冻结的决策理由、支持和反对证据、之后的价格路径、上面的确定性判定。输出是**封闭枚举的错误类型**，加一句话说明。初版枚举：

- `THESIS_WRONG`：机制判断错，比如判为延续，结果是反转；
- `IGNORED_OPPOSING`：反对证据已经在场，却被忽视；
- `TIMING`：方向对，入场早或晚；
- `STOP_PLACEMENT`：止损放在噪声内；
- `EXECUTION`：成交偏差吃掉了优势；
- `REGIME_MISMATCH`：整体行情和机制不匹配；
- `COST_DOMINATED`：预期盈利空间小于成本；
- `NONE_LUCK`：决策合理，结果是噪声。**这类不产生教训。**

复盘对象包括亏损单和盈利单。赢了但决策差（比如运气好没打止损），一样是要学的错误。

### 3.4 打法手册：唯一的教训存储

合并现有的 `ps_lessons`、`LearningHypothesis`、自动生成的 guard、memo、reasoning feedback、calibration feedback、draft skill（评估报告 G6）。每条字段：

| 字段 | 说明 |
|---|---|
| `id` / `version` | 修改即新版本，旧版本只停用不删 |
| `polarity` | `AVOID` / `PREFER` / `ADJUST`（修复评估报告 G4） |
| `scope` | 机制 × 方向 × 行情标签，**粗粒度、不按标的**。按标的的粒度太细，一辈子攒不够样本 |
| `trigger` | 可选：能在冻结输入上求值的条件，比如 `continuation 且 4h 涨幅 > 5%`。有它的规则可以离线回测 |
| `text` | ≤200 字，给 AI 读 |
| `error_type` / `source_decision_ids` | 来源，按唯一决策去重 |
| `helpful` / `harmful` / `last_used_at` | 计数器（学 ExpeL / ACE） |
| `status` | `candidate` → `active` → `retired`，只有三个状态 |

- **产生条件**：同一错误类型在同一范围、**≥3 个不同决策**里出现，由 LLM 起草，或修改已有规则。单笔不产生规则。
- **增量操作**：每次复盘批次只允许新增、修改、退役三种操作，不整体重写，以避免 ACE 论文里的"上下文坍缩"。
- **入库门**：AstraQuant 式 linter，禁止放宽止损、加杠杆、加仓位、降门槛；范围不得宽于来源证据；同 `scope + polarity + trigger` 视为重复，合并到已有规则。

### 3.5 应用：建议级直接用，授权级另走严格门

- **建议级**（owner 已同意）：入场分析上下文里按范围匹配，取 ≤5 条 `active` 规则（排序 = 净帮助数，经收缩后），带 `playbook:<id>` 可引用。AI 必须在 `lessons_considered` 逐条表态。规则**不能**拦截、不能改仓位或杠杆。
- **授权级**（不变，沿用现有严格门槛）：只有带 `trigger` 的 `AVOID` 规则可以申请。申请条件是：在**规则诞生之后**的决策上回放，命中组的扣成本 R 显著劣于未命中组；并且要对"历史上一共试过多少条规则"做多重检验折扣（Deflated Sharpe / Benjamini–Hochberg 思路）。通过后仍需 owner 准入。

### 3.6 计数与度量：怎么知道"真的学会了"

**规则级（每条规则自己的账）**，只用规则诞生后的决策：
- **`AVOID` 规则**：AI 因它放弃时，要求同时给出"本来会下的计划"（影子计划，D1）。回放影子计划：亏了记 `helpful`，赚了记 `harmful`。这正是"拦下来的本来会怎样"，AstraQuant 和 R20 都测不了，我们可以。
- **`PREFER` / `ADJUST` 规则**：被遵循的决策，与同范围内未遵循的决策比较回放 R，按收缩后的差值记账。
- **续期与退役**（修复评估报告 G5）：有帮助就续期。`harmful` 显著多于 `helpful`（n≥10 后经收缩判定）则退役。60 天无人使用则退役。`candidate` 30 天没升为 `active` 则清理。

**系统级（整个手册有没有用）：**
- **整包开关随机对照**：按规划代次（planning generation）的哈希，固定比例分到"有手册"和"空手册"两组；复用 Observation Lab 已有的空上下文对照通路（`mechanism_entry_learning`，`learning_contract.md` §12），不另造分组系统。
- **主指标是决策效用**：`ENTRY_PLAN` 计回放 R，`NO_PLAN` 计 0。
- **领先指标**：校准度（Brier 分）、规则遵循率、`NONE_LUCK` 以外错误类型的发生率。人类交易员的进步，首先体现在这些过程指标上。
- **检验方法**：随时可停的序贯检验（e 值）。**有害**一旦越过阈值，手册自动关闭，退回空手册。**有益**只用于报告，不用于扩大权限。
- **样本量粗估**（未核实，取单个决策 R 的标准差约 1.2）：每组 1,000 个决策，可检测 ≈0.15R 的差异。按当前决策速度，约需数周到两个月。收益差异在数周内测不出来是正常现象，过程指标会先动。

### 3.7 再往上一层：离线"重跑"做进化

前面 1–6 步稳定以后，可以加一层成本较高但很强的进化：把**历史冻结的决策输入**交给"新版手册"或"新版提示词"重新跑一遍 LLM，再用回放打分。这相当于在上线前先做一次纸面试卷（GEPA 式的提示词进化）。

- 只用模型知识截止日之后的冻结输入，避免模型"背答案"（look-ahead）。
- 按 token 成本控制规模。
- 这是"自升级"的正确形态：先离线证明，再进入线上对照。不能像 AstraQuant 那样让 LLM 直接改仓位乘数。

## 5. 分阶段落地（先能用，再变强）

| 阶段 | 内容 | 完成标准（可验证） |
|---|---|---|
| **P1 最小闭环** | ①决策回放标签；③复盘读冻结理由并输出错误类型；④打法手册单表加 linter；⑤建议级 ≤5 条注入，加 `lessons_considered`；⑦整包开关分组与有害自动关闭 | 冻结规划输入里出现 `playbook:` 引用；每个 ENTRY_PLAN 有回放 R；分组两组都有样本；本地确定性测试覆盖"有害触发自动关闭" |
| **P2 能分功劳** | `p_target_first` 与校准度；影子计划；规则级计数、续期、退役；`trigger` 离线回测 | 每条 active 规则都有 helpful/harmful；校准曲线可查 |
| **P3 授权与进化** | `AVOID + trigger` 授权申请（多重检验折扣 + owner 准入）；离线重跑评估新手册或新提示词 | 至少一次离线重跑报告；授权申请走完一次（结论可以是拒绝） |

P1 是 owner 要的"像人一样学"的最小可运行版本。草稿 PR #3935 的 H6（Planner 读教训）可以作为 P1 第⑤步的起点；它的 H5（按来源成交审核）被 §3.6 取代。

## 6. 诚实的预期

- **这套设计保证的**：学习不会悄悄变坏，因为有害会自动关闭；每条规则的来源、使用情况和效果都可查；样本量足以在数周内测出过程指标的变化。
- **这套设计不保证的**：一定赚钱。当前毛方向收益约为 0、来回成本约 0.24%，最可能先学会的是"什么时候别做"，即少做负期望的单子、少被成本吃掉。这已经是实打实的改进。至于能否学到正向优势，取决于市场里是否存在 AI 能识别的规律，这是实验结果，不是工程保证。
- **最大的不确定性**：
  1. 回放与真实成交的偏差（§3.1 要先测）；
  2. LLM 是否真的照规则做（`lessons_considered` 加遵循率会直接暴露）；
  3. 错误类型枚举是否够用（P1 跑两周后复审）。
